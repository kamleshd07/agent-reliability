# Qwen3-14B relevance citation failures: diagnosis and one config comparison (2026-11-08)

Local only (Ollama, qwen3:14b, digest bdbd181c33f2, no-think, 512 output tokens). Synthetic data. NOT a calibration; no human labels; no quality claim.

## Diagnosis (`scripts/p29_qwen_relevance_diagnostic.py diagnose`, output `diagnostic_3case.json`)
- Evidence sent for relevance: `role=question index=0` and `role=answer index=0`; **zero context blocks**.
- The system message says citations are "the index of a context block (role=context)"; Qwen nevertheless returns `"citations":[0]` in 2 of 3 cases (q01, q02), on both the initial call and the automatic repair call (5 provider calls in total); q03 returned `[]` and parsed. (An earlier draft of this record said 3 of 3 because the script mispaired repair calls with cases; the script is fixed and the output regenerated.)
- The unmodified strict parser rejects it (`invalid_citations`), correctly: index 0 does not exist as a context block. Rubric `require_citations` is false, JSON is valid, codes are valid, finish reason `stop`.
- Root cause: relevance has no context input, yet the shared output template still asks for context-block indexes; Qwen binds the only `index=0` it sees. This is a prompt-template gap, not a validator defect and not model truncation.
